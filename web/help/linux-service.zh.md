# Tunnel Helper 使用帮助

## 程序介绍
Tunnel Helper 是管理 SSH 密钥、连接档案和 SSH 隧道的可视化工具。Linux 版本可以运行在没有桌面的服务器上，通过浏览器访问；Windows 版本是桌面程序。
它可以用于将 VPN 或其他网络客户端放在虚拟机中，由虚拟机建立 SSH 隧道，让个人电脑通过隧道访问有权限的服务器。它不提供 VPN 本身，也不会自动绕过目标网络的访问限制。

## 主要功能
密钥管理：查看用户 ~/.ssh 和程序目录的密钥，导入、导出、删除密钥，或将选中的公钥合并成 bundle。导出公钥 bundle 不包含私钥。
密钥生成与安装：生成 Ed25519 密钥，可设置私钥密码；将公钥安装到服务器，然后验证密钥登录。
配置管理：保存多组服务器、端口、认证方式和密钥设置。可拖动档案调整顺序；反向隧道档案使用不同颜色标识。
连接配置：选择档案，检测服务器，启动 SSH 隧道，设置自动重连，生成或复制 SSH 配置。
Connections 和 Logs：查看或停止当前服务管理的隧道，以及查看操作日志。设置按钮可调整语言等界面选项。

## 开始使用
1. 确认运行程序的机器已安装 OpenSSH 客户端，并且能连接服务器的 SSH 端口。
2. 在“密钥管理”中查看已有密钥，或在“密钥生成与安装”中生成密钥、安装公钥并验证登录；也可以选择服务器密码认证。
3. 在“配置管理”中新增档案，填写服务器信息、认证方式和端口，保存后选择“应用到连接”。
4. 在“连接配置”中确认参数，按需要启用自动重连，然后点击启动。到 Connections 查看状态或停止隧道。
5. 按实际场景在个人电脑上使用生成的 SSH 配置。日志中的失败信息可用于排查网络、密钥和端口问题。

## 密钥与认证
私钥保存在发起 SSH 连接的机器上，公钥放在目标账户的 ~/.ssh/authorized_keys 中。不要把私钥发给他人或提交到公开仓库。
服务器密码用于登录服务器；私钥密码用于解锁加密的私钥，两者不是同一个密码。密钥生成时可留空私钥密码；设置后使用密钥需要解锁。
Linux 服务会调用本机的 ssh 和 ssh-keygen。填写服务器密码可用于后台安装公钥；使用已有登录密钥也可安装公钥。无图形界面的 Linux 模式不提供交互式终端安装，需填写密码或选择已有登录密钥。
导入到 ~/.ssh 前需要勾选允许导入；删除密钥会删除选中的私钥和对应公钥，请先确认选择及备份。

## 档案和保存位置
Linux 便携版默认在可执行文件同级的 data 目录保存 profiles.json、app_settings.json 和 ssh_keyfiles_export 密钥目录；也可以使用 --data-dir 指定其他目录。Windows 便携版使用自己的程序目录，两者配置相互独立。
档案可能包含服务器地址、用户名、密码或私钥密码；data 和 ~/.ssh 都可能包含敏感信息。迁移前确认文件内容，勿将个人配置和私钥上传到 GitHub。
点击“应用到连接”会先保存当前档案，然后将其参数带到连接配置。更改档案排序会影响默认优先选择的档案。

## 浏览器访问和安全
Linux 版默认监听 0.0.0.0:6789（全部 IPv4 网卡），并默认关闭 Token。网络和防火墙允许时，其他设备可通过运行服务的主机 IP 和 6789 端口访问。
默认无认证时，任何能访问网页的设备都可以管理隧道、配置和密钥，包括删除密钥或关闭服务。0.0.0.0 不仅限于局域网，确保使用可信网络和防火墙。
要启用持久 Token，在 data/server_settings.json 中写入以下内容，然后重启。程序会生成 accessToken 并保存在同一文件，下次重启继续使用；启动终端也会显示 Token。
```json
{ "listen": "0.0.0.0", "tokenEnabled": true }
```
Token 开关缺失、为空、null 或 false 时默认关闭。配置中的 listen 明确填写 127.0.0.1 时只监听本机，其他情况默认监听所有 IPv4 地址。也可以用 --listen 127.0.0.1 启动；命令行参数优先于配置文件。
HTTP 本身不加密，包括 Token 在内的网页数据会明文传输；跨不可信网络访问时请使用 SSH 等加密通道。
网页的“关闭服务”会停止该服务管理的隧道并退出；只关闭浏览器页面不会停止后台服务。

## 正向和反向隧道怎么选
A 是有固定地址的服务器；B 是运行 Tunnel Helper 的 Linux 主机；C 是个人电脑。下面地址仅用于举例，请替换为真实地址。
正向隧道：B 能连接 A，C 能访问 B 的网络地址。C 连接 B 的监听端口，隧道再转发到 A 的 SSH 服务。
反向隧道：B 能连接 A，但 C 不能直接访问 B。B 在 A 上建立回环监听端口，C 先连接 A，再通过该端口跳转到 B。

## 正向隧道填写示例
假设 A 的地址是 198.51.100.10，SSH 端口是 22，登录用户是 alice；B 的局域网地址是 192.168.1.20；C 能访问 B。
在 B 的配置管理或连接配置中填写：
反向隧道：否。
服务器用户：alice；服务器地址：198.51.100.10；服务器端口：22。
本地起始端口 / 本地端口：2222（B 上可用的监听端口）。
认证方式：选择密钥或密码。使用密钥时，可选密钥选择 B 上能登录 A 的私钥；私钥有密码时填写对应密码。
SSH 别名：例如 server-a，只是生成配置时使用的名称。
启动后，C 连接 192.168.1.20:2222，实际登录的是 A 的 alice 账户。C 到 A 的 SSH 登录也需要 A 接受的密钥或密码；B 监听的端口还需要能从 C 访问。

## 反向隧道填写示例
假设 A 的固定地址是 198.51.100.10，SSH 端口是 22，用户是 relay；B 无法被 C 直接访问，B 上 SSH 端口是 22、登录用户是 bob；C 能访问 A。
在 B 的配置管理或连接配置中填写：
反向隧道：是。
服务器用户：relay；服务器地址：198.51.100.10；服务器端口：22。这三项都是 A 的登录信息。
中转服务器监听端口：22022（A 上尚未占用的端口）。程序只在 A 的 127.0.0.1 上监听该端口。
本机登录用户：bob；本机 SSH 端口：22。这里的“本机”是运行 Tunnel Helper 服务的主机 B，不是打开浏览器的电脑 C。
认证方式和可选密钥：选择 B 登录 A 所使用的方式和私钥；对应公钥必须已经安装在 A 的 relay 账户下。私钥有密码时填写对应密码。
SSH 别名：例如 server-b，用于生成 C 上的 SSH 配置名称。
启动后，把生成的 SSH 配置复制到 C 的 SSH 配置文件，再从 C 连接 server-b。C 需要能够分别认证登录 A 和 B；生成的配置不会包含 B 上的私钥路径，可根据 C 的实际密钥位置补充 IdentityFile。A 的 SSH 服务需要允许 TCP 转发，B 的 SSH 服务需要正在运行。

## 常见问题
连接超时或拒绝连接：检查服务器地址、SSH 端口、网络和防火墙；先确认运行 Tunnel Helper 的机器能连接该服务器。
密钥认证失败：确认用户名、所选私钥、公钥安装位置和文件权限；私钥有密码时确认输入的是私钥密码。程序连接中转服务器使用的私钥与个人电脑连接时使用的私钥不一定相同。
端口被占用：正向模式检查运行程序的主机端口；反向模式检查中转服务器的监听端口。换一个未占用端口后重新启动。
反向隧道运行但无法登录：检查本机 SSH 服务和端口是否可用、中转服务器是否允许 TCP 转发，以及个人电脑是否分别拥有登录中转服务器和本机的凭据。隧道建立不代表最终 SSH 登录一定成功。
打开网页后界面未更新：确认访问的端口对应哪个程序进程；编译更新文件后需要停止旧服务、启动新程序，再刷新浏览器。

## 启动服务
在程序目录中运行以下命令，默认在所有 IPv4 地址监听 6789 端口：
```bash
./tunnel-helper
```
指定其他端口，例如 6790：
```bash
./tunnel-helper --port 6790
```
有图形桌面时，也可以双击程序；托盘支持取决于桌面环境。

## 查找运行中的服务
以下命令显示程序的进程号（PID）和启动命令：
```bash
pgrep -af tunnel-helper
```
查看 6789 端口的监听进程（替换为实际使用的端口）：
```bash
ss -ltnp | grep ':6789'
```
确认某个进程实际运行的文件路径，将 PID 替换为上一步查到的数字：
```bash
readlink -f /proc/PID/exe
```

## 关闭服务与连接
在浏览器页面右上角点击“关闭服务”，确认后会停止此服务管理的连接并退出。
图形桌面可在托盘菜单选择“关闭所有连接并退出”。关闭浏览器窗口只会关闭网页，不会关闭后台服务。
在终端前台运行时，按 Ctrl+C 可以正常退出。
双击或后台启动时，先用上面的命令找到正确的 PID，再执行（例如 PID 是 1234）：
```bash
kill 1234
```
普通 kill 会发送 SIGTERM，程序会尝试停止自己管理的连接，再退出。稍候重新检查进程和端口。不要随意使用 kill -9，它会阻止正常清理。
